# 20260525 AI 助手体验优化总方案

更新日期：2026-05-26

## 1. 方向定稿

SourceFlow 的 AI 目标不再是“聊天助手”，而是“AI 原生笔记代理层”。

未来笔记软件中，AI 应成为笔记的原生能力：人类能在笔记中完成的事务，AI 都应能在权限、预览、审计和回滚边界内完成。AI 可以写笔记、续写、改写、审稿、建链、提取任务、批量创作、整理目录、管理知识库，并逐步支持自动化执行。

本方案的核心结论：

- AI 写入不应以“自动插入一段 Markdown”为核心，而应以 `patch/diff` 为核心协议。
- 编辑器内流式体验应先采用 `ghost draft`，完成后生成可审阅补丁，再通过正式事务写入。
- 高风险写入不允许直接落盘，必须经过计划、预览、确认、事务提交、审计记录。
- Dock 保留复杂对话与 Agent 任务；高频写作、改写、续写进入编辑器内联体验。
- 长期目标是完整的笔记事务代理层，而不是继续堆叠零散 skill。

## 2. 当前问题

### 2.1 当前能力

Skill 体系已有 24 个入口，覆盖选区总结、改写、翻译、要点、问答、表格、脑图，以及笔记创作、续写、总结、提纲、润色、建链、体检、任务和项目计划。

Tool 体系已有 23 个后端工具：

- 16 个 L1 只读工具。
- 5 个 L2 低风险写入工具。
- 2 个 L3 中风险写入工具。

这些能力已经具备基础面，但体验仍偏“聊天生成内容”，没有形成稳定的编辑代理闭环。

### 2.2 核心缺陷

| 问题 | 影响 | 优先级 |
|------|------|--------|
| AI 输出在弹窗中流式预览，完成后才插入 | 用户感受不到 AI 在编辑器中工作 | P0 |
| 写入结果缺少 patch/diff 审阅 | 用户不知道 AI 会改哪里、怎么改、能否撤回 | P0 |
| `replace-selection` 使用 `document.execCommand("insertText")` | 事务、撤销和兼容性不稳定 | P0 |
| 上下文统一发送全文 | 长文档 token 浪费，续写和改写容易跑题 | P1 |
| 续写/创作 prompt 缺少范围约束 | AI 容易写太多、写整篇、重复已有内容 | P1 |
| Skill 和 Tool 两套体系割裂 | 右键 skill 不擅长查资料，Dock 工具不擅长编辑器内写入 | P1 |
| 工具确认卡信息不足 | 只显示工具摘要，看不到目标块、修改前后和影响范围 | P1 |
| 缺少内联指令和连续编辑 | 不满意只能重跑，不能像 Codex 一样继续调 | P2 |
| 缺少批量 Agent 工作流 | 不能批量整理、创作、建链、审稿或管理知识库 | P2 |
| AI 操作缺少独立历史和回滚入口 | 只能依赖普通 Ctrl+Z，不利于长期自动化 | P2 |

## 3. 总体架构

### 3.1 AI 原生笔记代理层

新增逻辑层：`Assistant Note Agent Layer`。

它不替代现有编辑器、Dock 或后端 API，而是位于 AI provider、skill、tool、Protyle 事务和笔记数据之间，统一处理：

- 上下文收集与裁剪。
- 意图识别与计划生成。
- patch/diff 生成。
- 工具 dry-run 与 apply。
- 编辑器 ghost draft 展示。
- 用户确认与权限策略。
- 正式事务提交。
- AI 操作审计和回滚。

标准工作流：

```text
用户触发
  -> 收集精准上下文
  -> AI 生成计划
  -> 读工具补充上下文
  -> 生成 patch/diff
  -> ghost draft / diff 预览
  -> 用户接受、拒绝或继续调整
  -> 正式事务提交
  -> 审计记录与可回滚历史
```

### 3.2 Patch 协议

所有写入型 AI 能力都应逐步统一到结构化 patch。

```ts
type AssistantEditPatch = {
    id: string;
    skillId: string;
    source: "skill" | "dock" | "agent" | "automation";
    target: "selection" | "block" | "note" | "notebook" | "workspace";
    risk: "L1" | "L2" | "L3" | "L4";
    summary: string;
    operations: AssistantPatchOperation[];
};

type AssistantPatchOperation = {
    id: string;
    type:
        | "insert-after-block"
        | "replace-selection"
        | "replace-block"
        | "append-note"
        | "create-note"
        | "create-child-note"
        | "move-note"
        | "rename-note"
        | "set-attrs"
        | "delete-block";
    targetId?: string;
    before?: string;
    after?: string;
    reason?: string;
};
```

阶段初期可以只覆盖 `insert-after-block`、`replace-selection`、`replace-block` 和 `append-note`。后续再扩展到笔记移动、重命名、属性、批量管理。

### 3.3 Ghost Draft 原则

编辑器内流式体验不直接写真实块。

- AI 流式输出先显示为临时 `ghost draft`。
- `ghost draft` 可以在当前块后、选区旁或 Dock 侧栏显示。
- 完成后转换为 patch/diff。
- 用户接受后才调用 Protyle 正式事务。
- Esc 取消只清理 ghost draft，不污染笔记数据。
- Ctrl+Z 只负责撤销已正式接受的事务。

这个方案比“流式过程中不断修改真实块”更稳，能避免破坏 Protyle undo/redo、选区和块事务。

### 3.4 权限等级

AI 自动化能力必须分级。

| 等级 | 行为 | 默认策略 |
|------|------|----------|
| 只读 | 搜索、读取、分析、生成建议 | 自动允许 |
| 建议 | 生成 patch，但不写入 | 自动允许 |
| 低风险写入 | 追加、创建草稿、创建子文档、打标签 | 默认确认 |
| 中风险写入 | 替换块、删除块、批量修改 | 默认确认 |
| 高风险写入 | 删除文档、批量移动、批量覆盖 | 默认禁止或逐项确认 |

自动化规则只能在明确授权后执行，且必须可暂停、可回滚、可审计。

## 4. 分阶段计划

### 阶段 1：上下文引擎与 Prompt 修复

目标：不改编辑器事务，先提升 AI 输出质量。

改动范围：

- `app/src/assistant/constants.ts`
- `app/src/assistant/common/note.ts`
- `app/src/assistant/skills/registry.ts`
- `app/src/assistant/skills/execute.ts`

主要任务：

- 新增 `buildAssistantNoteContextForSkill(context, skillId)`。
- 选区类 skill 只发送选区、当前块和必要结构，不发送全文。
- 续写只发送当前块、前后兄弟块、父标题链和大纲摘要。
- 创作发送主题、大纲、摘要和当前位置，不默认全量全文。
- 总结、提纲、问答、卡片使用全文摘要策略。
- 润色可读取全文，但需要明确输出范围和替换策略。
- 加入轻量风格感知：段落长度、列表比例、标题层级、中英比例。
- 重写所有写作类 prompt，严格限制续写 1-2 段、创作 2-3 段、输出不解释。

验收标准：

- 选区类 skill 不再发送整篇笔记。
- 续写结果默认只生成 1-2 个自然段。
- 创作结果不复述已有内容。
- TypeScript 编译通过。
- 不改变编辑器、后端、存储行为。

### 阶段 2：Patch/Diff 审阅模型

目标：建立 Codex 式“生成修改、审阅修改、接受修改”的核心闭环。

改动范围：

- 新增 `app/src/assistant/patch/` 模块。
- `app/src/assistant/skills/execute.ts`
- `app/src/assistant/ai/AIDockMessage.ts`
- `app/src/assistant/ai/AIDockRenderMessages.ts`
- 必要时新增轻量测试脚本。

主要任务：

- 定义 `AssistantEditPatch` 与 operation 类型。
- 将写入型 skill 结果转成 patch。
- 为插入、替换选区、替换块、追加笔记提供统一预览模型。
- 新增 diff 审阅 UI：接受全部、接受单项、拒绝单项、复制、继续调整。
- 工具确认卡升级为 patch 审阅卡，展示目标块、修改前后和风险。
- 自动应用模式降级为可配置，默认优先审阅。

验收标准：

- 写入型 skill 可先预览 diff 再应用。
- 用户能看到目标块、before、after 和理由。
- 未接受前不改变真实笔记。
- 前端行为测试覆盖接受/拒绝 patch。

### 阶段 3：Ghost Draft 编辑器内体验

目标：让用户感受到 AI 在编辑器内写作，但保持真实数据安全。

改动范围：

- 新增 `app/src/assistant/ghost/` 模块。
- `app/src/assistant/skills/execute.ts`
- `app/src/assets/scss/business/_assistant.scss`
- 仅使用 Protyle 外围 DOM，不改事务核心。

主要任务：

- 续写/创作在当前块后显示临时 ghost block。
- 选区改写/翻译在选区附近显示 inline ghost replacement。
- 流式 delta 更新 ghost draft，不写真实块。
- 流式完成后生成 patch/diff。
- Esc 取消 ghost draft。
- 接受后通过正式 Protyle/API 事务一次性提交。
- 移除 AI 替换路径中的 `document.execCommand("insertText")`。

验收标准：

- 续写和创作能在编辑器内流式显示。
- 取消不会留下真实块。
- 接受后 Ctrl+Z 能撤销正式事务。
- 不破坏选区、滚动和块结构。

### 阶段 4：内联指令与连续编辑

目标：高频 AI 编辑不再依赖 Dock 或右键菜单。

改动范围：

- 新增 `app/src/assistant/inline/` 模块。
- `app/src/assistant/skills/contextActions.ts`
- Protyle keydown 入口相关模块。

主要任务：

- `Ctrl+I` 打开内联指令面板。
- 支持自然语言指令：更简洁、翻译成英文、改成列表、加例子。
- 支持最近 5 条指令。
- 支持最多 3 轮连续编辑。
- 替换结果保持选中状态，便于继续调整。
- `Ctrl+J` 触发当前位置续写。

验收标准：

- 选区后 `Ctrl+I` 可调出面板。
- 结果走 ghost draft + patch 审阅。
- 连续编辑不会无限膨胀上下文。
- 快捷键不干扰已有编辑器快捷键。

### 阶段 5：工具事务化与 AI 审笔记

目标：把 AI 能力从写作扩展到真正的笔记事务代理。

改动范围：

- `kernel/model/assistant_ai_tools*.go`
- 新增前端 tool preview / dry-run 适配模块。
- 后端工具模块拆分，避免继续扩大单文件。

主要任务：

- 工具增加 `dryRun` / `preview` / `apply` 思路。
- 写工具默认先返回 patch，而不是直接执行。
- 补充笔记事务工具：重命名、移动、打标签、设置属性、创建双链、拆分文档、合并建议。
- AI 审笔记能力输出可执行 patch，而不是只输出报告。
- 审查维度包括结构、重复、引用、附件、行动项、孤立主题、表达质量。
- 修复编辑重发路径中 Anthropic/Gemini 原生 tool calling 一致性。

验收标准：

- 写工具可预览影响范围。
- AI 审笔记能生成可接受/拒绝的修改建议。
- 中风险操作默认确认。
- Go 单元测试覆盖核心工具策略。

### 阶段 6：批量 Agent、审计与自动化

目标：支持“AI 管理知识库”的长期能力。

改动范围：

- 新增 Agent 任务队列与进度 UI。
- 新增 AI 操作历史面板。
- 后续再评估是否将 AI 元数据写入块属性。

主要任务：

- 批量整理文件夹。
- 批量审查新增笔记。
- 从收集箱生成项目计划。
- 批量创建专题子文档。
- 批量建链和打标签。
- 支持暂停、恢复、失败重试和逐项 diff 审阅。
- 记录 AI 操作历史：patch、目标、时间、profile、状态、回滚入口。
- 自动化规则后置：新笔记摘要、每日整理、项目任务同步等。

验收标准：

- 批量任务可暂停、恢复、取消。
- 每个任务项都有可审阅结果。
- AI 操作历史可查看并回滚低风险写入。
- 自动化执行必须有明确用户授权。

## 5. 第一轮实施建议

第一轮只做阶段 1，不写编辑器事务，不改后端写工具。

原因：

- 低风险，能马上改善续写、创作、改写质量。
- 为 patch 和 ghost draft 提供更准确的上下文输入。
- 不会触碰 Protyle 事务和存储边界。

第一轮任务清单：

- 新增 skill-aware 上下文构建。
- 改造 `runAssistantSkill` 调用对应上下文。
- 重写写作类 prompt。
- 选区类不再附带全文。
- 增加风格感知描述。
- 补充前端行为测试或脚本验证。

## 6. 风险与边界

- Protyle 事务不能被流式 DOM 更新污染；真实写入必须在用户接受后一次性提交。
- `ai-*` 块属性属于持久化行为变更，不能在早期默认引入；应先用前端操作历史或独立审计表。
- Tool call 上限不应简单从 3 改为 5；应配置化，默认保持 3，高级模式再放宽。
- 批量 Agent 必须限制单次处理量，支持取消、超时和恢复。
- 删除、移动、批量替换等高风险操作默认禁止自动执行。
- 所有测试不得依赖真实外部 AI 服务，应使用 fake provider 或 mock stream。

## 7. 验证门禁

每个阶段必须至少完成：

- `git diff` 人工审查。
- TypeScript 编译或目标脚本验证。
- 涉及 Go 后端时运行目标 Go 测试。
- 涉及编辑器交互时补充前端行为测试。
- 写入行为必须验证撤销、取消、失败恢复。
- plans 文档同步更新后再提交。

## 8. 产品级补齐路线

更新日期：2026-05-26

当前 AI 助手已具备 skill-aware 上下文、基础 patch/diff、ghost draft、内联指令、工具 dry-run 预览、本地 Agent 队列与 AI 操作历史雏形，但这些能力仍未形成产品级闭环。后续开发按以下 8 个顺序推进，先修正验证和配置基础，再收敛写入事务，最后补批量 Agent 与端到端验收。

### 8.1 修复验证红灯和 ProfilesPanel 配置闭环

目标：确保现有 AI Dock 行为测试恢复稳定，并让模型配置流程可用、可理解、可失败恢复。

影响与边界：

- 后端 provider list 增加返回 `defaultModel` 与 `recommendedSettings`，属于向后兼容的响应字段扩展。
- 前端 ProfilesPanel 使用后端返回的默认模型和推荐参数填充新配置，不改变既有已保存 profile。
- 模型列表接口返回 `error` 时必须在 UI 显示明确失败原因，不再静默显示空列表。
- 本阶段不改变 AI 写入、工具执行或笔记数据。

验收：

- `pnpm --dir app run test:ai-dock-runtime` 通过。
- `pnpm --dir app exec tsc -p tsconfig.json --noEmit --pretty false` 通过。
- Provider 切换能自动填入默认 baseURL、默认模型和推荐参数。
- 模型列表失败时显示后端错误信息。

### 8.2 Tool 确认改为真正 Patch Review

目标：Dock 工具写入不再是“只读 patch 卡 + 确认直接执行”，而是统一进入可逐项接受/拒绝的 patch 审阅闭环。

影响与边界：

- 写工具在确认前默认只返回 `previewPatch`，真实写入必须由用户接受 patch 后触发。
- Dock 工具卡支持接受单项、拒绝单项、接受全部；不再把“确认执行”作为唯一写入路径。
- 后端工具确认 API 保留兼容，但前端优先走 patch apply；未生成可应用 patch 的工具继续阻断真实写入。
- 中风险写入仍默认确认，高风险和批量写入仍默认禁止自动执行。

验收：

- 工具 preview patch 可在 Dock 中逐项接受/拒绝。
- 未接受前不改变真实笔记。
- 接受后记录 AI 操作历史。
- 工具确认/拒绝行为测试覆盖 patch 路径。

### 8.3 补齐 Patch Apply Operations

目标：让后端能生成的低/中风险 patch operation 在前端具备一致的应用能力，避免“能预览但不能落地”。

首批补齐：

- `create-note`
- `create-child-note`
- `delete-block`
- `rename-note`
- `set-attrs`

影响与边界：

- `delete-block`、`rename-note`、`set-attrs` 属于中风险写入，必须保持确认。
- 不支持的 operation 必须明确标记为仅预览，不允许用户误以为可应用。
- 每个 operation 应使用现有后端 API 与正式事务路径，不引入直接文件写入。

验收：

- 支持的 operation 可应用、可失败提示、可写入历史。
- 不支持的 operation UI 明确不可应用。
- patch 脚本测试覆盖各 operation。

### 8.4 重做选区替换可靠性

目标：替换选区不再依赖 `blockMarkdown.replace(before, after)` 的首个字符串匹配，降低重复文本误替换风险。

影响与边界：

- 替换前必须校验目标块、原文片段和当前块内容一致性。
- 当同一 `before` 在块中出现多次时，默认不自动替换，提示用户改用复制或重新选择。
- 后续可引入更精确的选区 offset / transaction 定位；本阶段先禁止高风险模糊替换。

验收：

- 重复文本不会被静默误替换。
- 选区替换失败时保留复制结果和重新生成路径。
- 回归测试覆盖重复文本、缺失 before、正常替换。

### 8.5 打磨 Ghost Draft 和 Inline 连续编辑

目标：让编辑器内 AI 写作体验从“能显示”升级为稳定、可继续调、少打断。

影响与边界：

- ghost draft 仍只使用临时 DOM，不写真实块。
- 审阅弹窗打开后 ghost 状态不能闪烁或提前消失。
- 内联继续调整应基于“原始选区 + 上轮结果 + 新指令”，接受或拒绝后释放连续轮次限制。
- 快捷键必须避免覆盖既有编辑器冲突。

验收：

- 取消、失败、重试、继续调整都有明确状态。
- 连续编辑最多 3 轮且可在接受/拒绝后重置。
- 目标脚本和 TypeScript 编译通过。

### 8.6 实现真正 Agent 执行器

目标：把当前本地 Agent 队列和历史面板扩展为可执行、可暂停、可恢复、可取消的批量任务系统。

影响与边界：

- 批量任务必须限制单次处理数量、并发数和超时。
- 每个任务项输出 patch，用户逐项审阅后才写入。
- 暂停/取消必须释放资源，不继续发起新的 AI 请求。
- 自动化规则只记录设计，不默认启用后台自动执行。

验收：

- 可创建批量任务并逐项执行。
- 暂停、恢复、取消、失败重试可用。
- 每项都有状态、错误原因和 patch 审阅入口。

### 8.7 AI 操作历史产品化

目标：把本地 best-effort 历史升级为更可靠的审计记录与回滚入口。

影响与边界：

- 历史记录应包含 patch、目标、profile、时间、状态、应用结果和失败原因。
- 回滚优先覆盖低风险追加/插入/创建类操作；中风险回滚必须再次确认。
- 不记录 API Key，不输出敏感请求头。

验收：

- 历史可按最近操作查看。
- 低风险写入可回滚。
- 失败状态可审计。

### 8.8 建立 Fake Provider 端到端验证和 GUI 冒烟清单

目标：产品级验收不依赖真实外部 AI 服务。

影响与边界：

- 新增 fake provider / mock stream 用于测试配置、流式、patch、工具和 Agent 流程。
- GUI 冒烟清单覆盖中文/英文、无配置、有配置、网络失败、长文档、重复选区文本。
- 不引入真实外部服务依赖。

验收：

- fake provider 端到端测试覆盖 AI 主流程。
- GUI 冒烟清单纳入 `plans/` 或测试文档。
- 发布前可复现验证结论。
