# 20260602 工作台稳定化与 AI 原生笔记安全设计

更新日期：2026-06-02

## 1. 已确认方向

- 工作台与 AI 是两个独立功能，分别开发、分别验收。
- 工作台定位为任务、项目、资料、视图、收件箱、日历、查询筛选的生产力工作区。
- AI 定位为 AI 原生笔记助手，是可引用、可审阅、可授权、可审计地操作笔记系统的智能控制层。
- 默认应把工作台和 AI 固定在侧边栏，不能藏在“更多功能”里作为低优先级入口。
- 工作台当前已有实现，下一步优先解决入口空白和功能稳定性，不重做产品定位。
- AI 后续开发必须同时具备笔记层安全设计与 AI 层安全设计，安全内核优先级高于 profile、prompt、工具调用和自动化规则。

## 2. 外部产品参考原则

本设计只吸收产品原则，不照搬具体交互。

- Notion AI：AI 位于工作区内，可使用工作区和连接应用上下文，支持内联写作、页面/数据库编辑、计划审阅与批准。
- Tana AI：可从任意 note 直接开启 AI chat，支持通过 `@` 引用具体笔记上下文，支持独立 AI chats 侧边栏和模型选择。
- NotebookLM：以 sources 为核心组织对话，用户可添加、移除、勾选来源，回答和生成内容围绕用户提供来源展开。

官方参考：

- https://www.notion.com/help/notion-ai-faqs
- https://outliner.tana.inc/learn/features/ai-chat
- https://outliner.tana.inc/learn/features/tana-ai
- https://support.google.com/notebooklm/answer/16206563

## 3. 任务一：工作台稳定化

### 3.1 目标

让工作台作为独立生产力工作区稳定可用：

- 侧边栏默认固定工作台入口。
- “更多功能 -> 工作台”等入口不能打开空白。
- 空数据、坏本地状态、懒加载失败、查询失败都必须有可理解 UI，不允许白屏。
- 不改变工作台已有数据结构、查询语义、元数据语义和任务/项目定位。

### 3.2 当前判断

代码中已有 `app/src/workbench/` 模块，覆盖 dialog、query、render、events、metadata、draft、saved views、view note 等能力。入口也已通过 activity bar 懒加载 `openWorkbenchDialog`。

用户反馈“打开一篇空白，无法使用”说明问题大概率在入口路由、懒加载异常、空状态渲染、坏存储状态或错误兜底，而不是工作台完全未实现。

### 3.3 实施阶段

1. 入口收敛
   - 检查活动栏、更多功能、标题菜单、捕获设置、保存视图等入口。
   - 所有入口统一调用 `openWorkbenchDialog` 或明确的工作台子入口。
   - 默认将 `action:workbench` 固定到侧边栏 rail。

2. 空白兜底
   - dialog 创建失败显示错误。
   - 模块懒加载失败显示错误。
   - 查询失败显示错误和重试入口。
   - 查询结果为空显示可操作空状态，而不是空容器。
   - 本地存储中的坏 state 必须归一化到默认状态。

3. 功能冒烟
   - 打开工作台。
   - 切换 tab。
   - 输入查询。
   - 切换列表/表格/看板/时间线/月历。
   - 打开保存视图。
   - 编辑当前文档或块的工作台元数据。
   - 插入动态视图到当前笔记。

4. 验证
   - 增加工作台入口与空状态结构测试。
   - 运行 `pnpm --dir app run typecheck:app`。
   - 执行 `git diff --check`。

## 4. 任务二：AI 原生笔记助手

### 4.1 目标

AI 不再只是聊天框，而是可控制整个软件的笔记代理层：

- 能在笔记、选区、文档树、文件夹、附件、搜索结果、工作台视图等笔记元素上直接触发。
- 能打开独立对话 Dock，并用 `@` 引用任意允许访问的上下文。
- 能读取、分析、写入、执行软件内操作，但所有能力受权限、安全、审阅、审计约束。
- 支持多个 AI profile，调用时可选择写作模型、长上下文模型、本地模型、低成本模型等。
- 默认写入走 `patch/diff` 审阅，接受后才通过正式事务落盘。

### 4.2 核心模块

1. AI 入口层
   - 侧边栏固定 AI Dock。
   - 笔记编辑器选区入口。
   - 标题菜单入口。
   - 文档树右键入口。
   - 文件夹/附件/搜索结果入口。

2. 上下文引用层
   - 支持 `@当前笔记`、`@选区`、`@笔记`、`@文件夹`、`@附件`、`@搜索结果`、`@工作台视图`。
   - 文件夹和大量笔记引用必须先构建上下文包，不允许无界塞全文。
   - 上下文包包含路径、标题、摘要、关键块、最近变更、可按需读取的 source ID。
   - 回答应能显示来源引用，尤其是文件夹、附件、搜索结果和跨笔记问答。

3. Profile 与模型选择层
   - 多 provider/profile 保存。
   - 每次对话或任务可选择 profile。
   - 可配置默认 profile、写作 profile、长上下文 profile、本地隐私 profile。
   - profile 不得绕过权限和安全内核。

4. 权限内核
   - 三种模式：默认权限、自动审查、完全访问权限。
   - 三类能力：可读、可写、可执行。
   - 黑白名单按笔记本、文件夹、笔记、标签、附件类型、工具类型配置。
   - 黑名单优先级高于白名单。
   - 权限判断发生在上下文读取、计划生成、工具 dry-run 和正式 apply 前。

5. 安全内核
   - 笔记层安全负责保护数据边界、事务、路径、范围和回滚。
   - AI 层安全负责识别模型意图、工具计划、绕过行为和批量风险。
   - 安全内核优先级高于用户 profile 和 prompt。

6. Patch 与执行层
   - 写入型能力默认输出 patch。
   - patch 需要包含目标、影响范围、风险、before/after、理由和来源。
   - 用户接受后通过正式 Protyle/API 事务写入。
   - 执行结果必须写入 AI 操作历史，支持失败审计和低风险回滚。

## 5. 笔记层底层安全设计

### 5.1 硬禁止操作

AI 永远不能执行以下操作，即使在“完全访问权限”下也不能授权继续：

- 删除整个工作空间。
- 删除整个笔记本。
- 清空所有笔记。
- 清空某个笔记本下全部笔记。
- 重置工作空间数据。
- 通过导入、同步、覆盖、迁移等方式变相替换整个工作空间或笔记本。
- 将全量笔记批量替换为空。
- 将所有笔记移动到废纸篓后自动清空。
- 直接调用底层文件系统删除工作区、笔记本根目录或全量 `.sf` 文件。

AI 对这类需求只能生成清理建议、风险报告或人工操作清单。

### 5.2 单篇和批量操作

- 单篇笔记删除不是硬禁止，但属于高风险操作，必须人工确认。
- 单篇笔记写入、重命名、移动、属性修改按风险进入 patch 审阅。
- 单次任务触达 `>= 10` 篇笔记的修改、删除、移动、重命名、属性批改，必须人工确认。
- 批量阈值按同一会话、同一 Agent 任务、同一用户目标累计计算，不能被拆成多次 9 篇绕过。
- 文件夹级操作必须先展开影响清单，展示笔记数量、路径、操作类型和风险等级。

### 5.3 数据写入约束

- AI 不直接写文件系统。
- AI 写入必须走笔记原生 API、事务队列和 patch apply。
- 写入前必须校验目标仍存在、目标属于授权范围、目标内容与 patch 的 before 一致。
- 目标路径必须在笔记本根目录内，禁止 `..`、绝对路径、卷标路径和符号越界。
- 外部 Markdown 写入必须重新生成块 ID，避免 ID 碰撞。
- 删除块、替换块不得作用于根文档块；无法确认 root 关系时失败关闭。
- 附件默认只读；附件写入、移动、删除必须单独授权。

### 5.4 审计与回滚

- 所有 AI 写操作记录 session、profile、权限模式、目标、来源、patch、结果、错误和时间。
- 低风险追加、插入、创建类操作提供回滚。
- 中高风险回滚必须再次确认。
- 失败写入也必须记录审计，不能静默失败。
- 审计记录不得保存 API Key、鉴权头或敏感请求体。

## 6. AI 层底层安全设计

### 6.1 绕过护栏检测

出现以下情况时，AI 执行必须暂停并进入安全拦截：

- 要求关闭、绕过、忽略安全检查。
- 要求静默执行或不要让用户确认。
- 试图分批规避 `>= 10` 篇笔记确认阈值。
- 用多个低风险工具组合达成高风险结果。
- 用移动、导入、同步、覆盖间接达成全量删除或全量替换。
- 请求直接调用底层文件 API 绕过笔记事务。
- 目标范围模糊，例如“全部”“所有”“整个库”，但没有人工确认后的影响清单。
- patch 目标与用户引用上下文不一致。
- 工具计划要求删除工作空间、笔记本或全量笔记集合。

硬禁止操作不能授权继续；其他高风险操作必须展示影响清单并由用户明确确认。

### 6.2 风险分级

- L1 只读：搜索、读取、总结、问答、生成建议。
- L2 建议：生成 patch、生成计划、生成可复制内容，不写入。
- L3 低风险写入：追加、插入、创建草稿、创建子笔记、设置低风险属性。
- L4 中风险写入：替换块、删除块、重命名、移动、批量低风险写入。
- L5 高风险操作：删除单篇笔记、批量修改/删除/移动、执行软件命令、导入覆盖、同步类变更。
- L6 硬禁止：删除工作空间、删除笔记本、清空全部笔记、重置数据、全量替换为空。

默认权限只允许 L1/L2，写入必须审阅。自动审查可让 L3 快速确认，L4/L5 人工确认。完全访问权限可减少低风险确认，但 L5 仍需确认，L6 永远禁止。

### 6.3 权限模式

1. 默认权限
   - 默认只读和建议。
   - 所有写入进入 patch 审阅。
   - 执行类工具默认不可用。

2. 自动审查
   - 可读取更多授权上下文。
   - 低风险写入可快速确认。
   - 中高风险自动升格到人工确认。
   - 检测到绕过意图时暂停。

3. 完全访问权限
   - 允许 AI 主动读取、写入和执行更多软件操作。
   - 仍受黑白名单、批量阈值、硬禁止和绕过检测约束。
   - 所有操作仍写入审计。

## 7. 开发顺序

### 阶段 A：文档和安全设计

- 固化工作台与 AI 独立开发。
- 固化 AI 笔记层和 AI 层安全内核。
- 更新计划文档和任务队列。

### 阶段 B：工作台稳定化

- 固定侧边栏入口。
- 修复工作台打开空白。
- 补空状态、错误兜底和入口测试。

### 阶段 C：AI 入口与上下文引用

- 固定 AI 侧边栏入口。
- AI Dock 默认可用，空配置显示明确引导。
- 支持 `@` 引用当前笔记、选区、笔记和文件夹。
- 多 profile 调用选择进入主链路。

### 阶段 D：权限与安全内核

- 实现权限模式、读写执行能力、黑白名单。
- 实现硬禁止、批量阈值、绕过检测和影响清单。
- 所有 AI 工具调用先经过安全内核。

### 阶段 E：来源型问答与附件

- 类 NotebookLM sources 模型。
- 支持勾选/排除来源。
- 回答显示来源。
- 附件先只读元数据和可解析文本，图片/OCR 后续单独设计。

### 阶段 F：AI 操作笔记闭环

- 文档树、标题菜单、选区和附件入口触发 AI。
- 输出 patch，用户接受后写入。
- 批量 Agent 逐项执行、逐项审阅、可暂停、可取消、可回滚。

## 8. 非目标

- 不把工作台改成 AI 工作台。
- 不让 AI 直接写文件系统。
- 不允许 AI 删除工作空间、笔记本或全量笔记集合。
- 不在第一阶段引入后台自动化常驻执行。
- 不让外部真实 AI 服务成为测试依赖，验收仍应支持 fake provider。

## 9. 验收口径

工作台验收：

- 侧边栏可见工作台入口。
- 打开工作台不白屏。
- 空数据、异常、坏状态都有 UI。
- 已有查询、视图、元数据和保存视图能力可用。

AI 验收：

- 侧边栏可见 AI 入口。
- AI 对话可引用笔记、选区、文件夹和附件。
- 三种权限模式可选择。
- 黑白名单和读写执行权限生效。
- `>= 10` 篇笔记的批量操作必须确认。
- 删除工作空间、笔记本或全量笔记集合被硬拦截。
- 绕过护栏意图会暂停并给出原因。
- 写入默认 patch 审阅，接受后正式事务写入，审计可查。
