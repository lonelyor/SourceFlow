# SourceFlow 架构与设计摘要

更新日期：2026-06-04

## AI 助手

- AI 助手前端 Dock 以 `AIDockRuntime` / `AIDockInstance` 作为外部入口，原有大文件逻辑拆分到控制器、状态、消息、事件和渲染模块。
- `AIDockContract.ts` 定义 Dock runtime 需要的状态和方法，是模块之间的类型边界。
- 消息发送、编辑重发、图片附件、工具确认、会话分析和插入最新回答集中在 `AIDockMessage.ts`。
- 会话、模型、目标笔记、工具策略和审计刷新集中在 `AIDockState.ts`。
- DOM 事件绑定和动作路由集中在 `AIDockEvents.ts`，渲染输出保持在 `AIDockRender*` 模块。
- AI 助手长期形态升级为 AI 原生笔记代理层：Dock 负责复杂对话与 Agent 任务，编辑器内联入口负责高频写作、改写、续写和审阅。
- 写入型 AI 能力统一到 `patch/diff` 协议，先生成可审阅修改，再由用户接受后通过后端安全入口提交；前端不得把 AI 生成内容直接写入普通块/文件树接口。
- 编辑器内流式体验采用 `ghost draft` 原则：流式阶段只显示临时预览，不直接写真实块；接受后再提交 Protyle/API 事务。
- AI 工具能力按只读、建议、低风险写入、中风险写入和高风险写入分级；高风险和批量操作默认不可自动执行。
- 产品级目标要求 Dock 写工具优先返回 `previewPatch` 并进入 patch review；用户接受 patch operation 后才调用正式写入 API。旧的工具确认 API 保留兼容，但前端不应把"确认执行工具"作为默认写入路径。
- 当前 Agent 能力边界为队列与历史外壳；产品级 Agent 需要独立执行器，负责任务逐项调度、取消、暂停、恢复、失败重试、超时和逐项 patch 审阅。
- Agent 面板创建批量任务时复用 Dock 当前输入作为任务列表，任务项必须保存待审阅 patch 与最小笔记上下文；暂停/取消需要中止当前执行请求，恢复/重试必须重新进入同一执行器。
- AI 操作历史先采用本地持久化审计模型，记录 patch、session/profile、目标、状态、应用结果和失败原因；低风险回滚覆盖追加/插入块以及 AI 创建的新笔记，后端审计表留待确认存储边界后再引入。
- Provider 配置列表应返回默认 baseURL、默认模型和推荐参数，前端 ProfilesPanel 使用这些字段初始化新 profile；模型列表失败必须向用户展示后端错误原因。
- AI 助手验收必须提供不依赖外部服务的 `fake` Provider：默认 baseURL 为 `sourceflow://fake`，默认模型为 `sourceflow-fake-chat`，不要求 API Key，支持配置连通测试、静态模型列表、确定性普通回复、mock stream，以及工具 dry-run patch 预览。该 Provider 仅用于本地测试和产品验收，不应作为真实生产模型接入。
- 前端 patch apply 必须复用后端 AI 写工具的安全边界：`delete-block` 和 `replace-block` 只能作用于非根内容块；无法确认目标块根文档关系时必须失败关闭，禁止直接删除或整体替换笔记根文档。
- AI/Assistant 产生的外部 Markdown 写入必须重新生成块 ID，避免导入内容携带的 ID 与现有笔记碰撞；普通块 API 默认保持兼容，仅在 `sanitizeIDs` 显式开启时执行。
- Embedding 配置 API 不得回显已保存 API Key；语义搜索结果限制最多 50 条，删除笔记时必须清理对应向量索引。
- AI Profile 与 Embedding 的 API Key 语义必须显式化：后端响应只返回 `hasAPIKey`，不得回显真实密钥；前端有密钥时只显示掩码 `******`，无密钥时显示空；保存请求必须携带 `apiKeyAction`，取值为 `keep`、`replace`、`clear`。`keep` 仅保留后端已有密钥，`replace` 使用本次输入的新密钥，`clear` 写入空密钥。掩码只作为 UI 展示状态，不得作为真实密钥存储或发送给模型服务。
- Embedding 全量索引和语义搜索等异步 UI 必须在成功、业务失败和网络失败路径都恢复按钮/loading 状态，不允许让用户停留在永久“索引中/搜索中”。
- 工作台与 AI 是独立功能：工作台负责任务、项目、资料、视图、收件箱、日历和查询筛选；AI 负责原生笔记助手、上下文引用、对话、patch 审阅、权限和审计。两者可以通过"引用当前工作台视图"或"让 AI 分析当前视图"做薄桥接，但不能合并为同一主入口。
- 工作台和 AI 都应默认固定在侧边栏活动栏，不应默认隐藏在"更多功能"中。
- 左侧活动栏的"更多"是溢出入口，必须渲染在所有可排序 rail 按钮之后；固定的备份/设置分区仍保留在分隔线之后。
- AI Dock 未配置 profile 时必须明确要求用户配置真实 AI 提供商和模型；不得把测试用 fake provider、本地验收 provider 或并不存在的本地模型包装成用户可用入口。配置完成前输入区和发送入口应处于不可发送状态，但配置按钮必须可见且统一打开 AI 设置页。
- AI 历史会话置顶以 `ai_sessions.pinned_at` 作为唯一持久状态源；重复置顶必须保持原 `pinned_at` 不变，避免非幂等刷新改变排序。前端刷新和本地 upsert 使用同一个会话排序 helper：置顶优先，再按更新时间排序。
- AI Dock `@` 引用搜索必须在前端先归一化 query；空 query 不请求后端，避免输入单独 `@` 时触发 `query is required`。
- 文档树节点和空白菜单的 AI 入口统一显示为 `@AI`，文案常量集中在 `assistant/constants.ts`；入口应将右键目标转换为来源面板来源，而不是仅写入普通提示文本。
- AI 目标笔记在未固定状态下跟随当前活动编辑器；打开 Dock 不得无条件覆盖已固定目标。固定目标与跟随当前笔记是互斥状态。
- AI 设置页中模型配置、Embedding 配置与安全配置共用同一滚动设置容器，避免后续分区被 `overflow:hidden` 裁切；新增设置分区样式归入 `.assistant-config__section`。
- AI 助手生产级加固继续遵循“AI 写入先预览、后审阅、再提交”的单一写入语义：前端 patch 接受、内联翻译替换、技能结果插入/替换/建链等会改变已有笔记内容的 AI 写入动作，不应直接调用普通块/文件树写接口，应通过后端 `/api/assistant/patch/apply` 入口完成安全检查、目标归一化、正式写入和结果审计。
- 后端 AI 写工具默认只生成 `previewPatch`，不得在 Dock 默认路径中直接执行真实写入；旧工具确认直写能力仅作为兼容路径保留，并应由显式参数或受控调用触发。
- `@` 引用与来源上下文 API 必须对空 query 返回空结果，不把用户输入过程中的临时空查询视作错误；上下文包构建必须返回被纳入和被丢弃来源的可解释状态，避免用户误以为未读取成功的来源已进入 prompt。
- 来源上下文必须有全局字符/token 预算，预算常量集中在后端模型层；文件夹、批量来源和前端拼接都必须以预算后的后端 context pack 为准。
- AI Profile 当前生产配置源为 `ai_profiles` 表；旧 `Conf.AI.OpenAI` 只应作为一次性迁移来源或非 AI 助手兼容边界，不再由 AI Profile 保存/删除反向同步。旧 `model/ai.go` 仍属于非 AI 助手兼容边界，后续如迁移需单独确认调用方。
- Agent 队列和 AI 操作历史当前仍有本地持久化边界；产品级持久审计和多窗口执行锁需要迁移到后端任务/审计表，作为独立阶段处理。

### AI 原生笔记助手架构（v2，2026-06-02 定稿）

详细设计见 `plans/20260602-AI原生笔记助手架构设计.md`。

- AI 原生笔记助手定位：AI 是笔记系统的智能控制层，能在笔记、选区、文档树、文件夹、附件等所有笔记元素上直接触发和操作，也能打开独立对话 Dock 并通过 `@` 引用任意允许访问的上下文。
- 双轨入口：编辑器内联（Ctrl+I/Ctrl+J/选区浮条）负责轻量操作（续写、改写、翻译），Dock 对话负责复杂操作（跨笔记、Agent 批量、来源感知问答）。两个入口共享统一安全内核、patch 审阅、AI 操作历史和 profile/模型选择。
- `@` 引用系统：Dock 输入框支持 `@` 触发搜索面板，可引用笔记、选区、文件夹、附件、搜索结果。引用后插入 inline chip 标签，右侧展开来源面板。
- 来源面板（类 NotebookLM Sources）：位于 Dock 消息区上方、输入区上方，可收起。列出所有引用来源，每个来源可勾选/排除/展开查看摘要。文件夹引用展开后显示子笔记列表，可逐项勾选排除。来源面板顶部显示 token 用量估算。发送时只包含勾选的来源。
- 引用上下文策略：笔记发送标题+摘要+关键段落（上限 2000 字）；选区发送选中文本+所在块上下文；文件夹先发送子笔记标题列表+各笔记摘要（每篇上限 200 字），AI 需要细读时通过 `read-note` 工具按需读取；附件发送可解析文本（PDF 提取/代码文件/图片 OCR）；搜索结果发送匹配笔记摘要集合。AI 回答标注来源，段落末尾追加 `[📄 笔记标题]` 标签，可点击跳转。
- 权限模式：会话级默认模式 + 单次操作可临时提权。三种模式：默认权限（只读+建议，L1/L2 自动允许）、自动审查（L3 低风险快速确认，L4/L5 人工确认）、完全访问权限（L4 快速确认，L5 仍需确认，L6 永远禁止）。提权弹窗展示操作类型、风险等级和目标，用户可选"本次允许"、"提升为自动审查"或"拒绝"。
- 黑白名单：独立存储在 `storage/ai_security.json`，不与 `conf/assistant.json` 合并。黑名单指定永远禁止 AI 操作的笔记本/文件夹/笔记；白名单指定自动审查模式下快速确认的范围。黑名单优先级最高。能力开关控制可读/可写/可执行/可创建笔记/可删除块/可删除笔记/可移动笔记。
- 安全内核四层检查：第 1 层硬禁止（删除工作空间/笔记本/清空全部 → 直接拒绝）；第 2 层黑白名单检查（黑名单拒绝，非白名单高风险需确认）；第 3 层批量阈值检查（同一会话/Agent/目标累计 >= 10 篇 → 人工确认+影响清单）；第 4 层绕过检测（分批规避、组合低风险达成高风险、直接调底层文件 API、模糊大范围目标 → 暂停+警告）。硬禁止操作不能授权继续。
- AI 回答来源标注格式：回答段落末尾追加 `[📄 笔记标题]` 内联标签，可点击跳转到对应笔记或块。多来源时标注多个标签。

### AI 安全内核独立存储

- 安全配置由 `kernel/model/assistant_security.go` 负责，持久化为 `storage/ai_security.json`。
- 包含：权限模式默认值、黑名单列表、白名单列表、能力开关、批量阈值。
- 不与 `conf/assistant.json` 合并，避免安全配置变更频率与 AI 模型配置互相影响。
- 配置读写必须经过 `NormalizeAISecurityConfig`，统一补默认值、裁剪批量阈值、归一化权限模式和黑白名单条目。
- Dock 聊天、流式聊天、编辑、工具确认、`@` 来源搜索和上下文包构建都必须透传当前 `securityMode`，后端缺省时回落到安全配置默认模式。
- Patch review 接受 `append-note`、`insert-after-block`、`replace-selection`、`replace-block`、`create-note`、`create-child-note`、`delete-block`、`rename-note`、`set-attrs` 前必须调用后端安全检查 API；后端返回硬禁止、黑名单或能力关闭时不得进入一次性提权。
- 单次提权只允许处理后端标记为 `escalatable` 的权限模式/人工确认结果；“本次允许”必须由后端签发短期一次性 token，并绑定当前 tool 或 patch operation 的 ID、目标、风险、能力和内容摘要，消费一次后失效；前端不得通过普通布尔值绕过安全决策。“提升为自动审查”必须同步更新当前 Dock 会话安全模式。
- 前端不得复制 AI 安全配置默认能力矩阵；设置页和 Dock 只能使用后端 `getConfig` 返回的归一化配置，加载失败时失败关闭或保留当前会话状态。
- 来源引用发送时只持久化 ID、类型、标题、路径等定位元数据；正文摘要仅作为当次 system prompt 上下文，不写入消息 metadata。

### AI 原生笔记助手开发阶段（v2）

- 阶段 1（最高优先级）：`@` 引用引擎 + 来源面板 + AI 回答来源标注。完成后 AI 从普通聊天框升级为可引用笔记元素的笔记助手。
- 阶段 2：权限模式切换 + 黑白名单 + 安全内核 + 提权弹窗。完成后 AI 操作具备完整的权限和安全约束。
- 阶段 3：编辑器入口统一 + 来源感知回答 + 文档树右键 AI 入口。完成后双轨入口体验一致。
- 阶段 4：Agent 增强 + 来源追溯 + 自动化规则设计。完成后 AI 支持完整的批量操作和自动化基础。

## 工作台

- 工作台是独立生产力工作区，不是 AI 工作台。
- 工作台已有 `app/src/workbench/` 模块，后续优先保证入口稳定、空状态可用、错误可见和已有功能闭环，不改变工作台数据结构和查询语义。
- 工作台入口应统一收敛到 `openWorkbenchDialog` 或明确的工作台子入口；入口加载失败、查询失败、坏本地状态和空数据都必须有 UI 兜底，不允许白屏。

## 发布约束

- 发布版本号由 `app/package.json`、`kernel/util/working.go` 和 Windows Appx manifest 共同约束，编译前必须保持一致。
- 发布说明存放在 `app/changelogs/v<version>/`，中文版作为默认 GitHub Release 正文。
- `发布.py` 只消费 `编译.py` 已生成并验证的产物，不在发布阶段重新编译。
- `编译.py` 默认启用自动并行作业，`--jobs 0` 按 CPU 自适应解析，当前默认上限为 4；前端多 bundle、前端与 kernel 准备、Go 测试可以并行，但 installer 与 portable 打包必须保持串行。
- Windows portable 打包可复用 installer 遗留的 `win-unpacked`，因此不得与 installer 并行写同一个 `app/build`；如后续要并行打包，必须先隔离输出目录和复用策略。
- `编译.py` 必须输出阶段耗时汇总，用于定位质量门、前端构建、kernel 构建、installer、portable 和验证等瓶颈；并行子任务耗时可以重叠，只有总耗时代表 wall-clock。
- `编译.py` 和 `发布.py` 必须支持 Ctrl+C 优雅取消：第一次中断设置全局取消信号、停止活跃子进程并在短等待后强杀仍存活进程，第二次中断立即强杀；顶层取消退出码为 130，且不得输出 Python traceback。
- 构建/发布脚本启动的长耗时子进程必须通过统一 `run()` 包装器登记；验证中手动启动的进程必须在 `finally` 中清理；清理命令不得被取消标记阻断。
- 构建/发布脚本输出使用统一状态行表达关键状态：`[RUN]`、`[OK]`、`[FAIL]`、`[CANCEL]`；失败和取消摘要必须简洁并包含可行动原因。
- `发布.py` 默认并行上传 GitHub Release 独立资产，默认并行度为 3，可通过 `SOURCEFLOW_RELEASE_UPLOAD_JOBS` 或 `--upload-jobs` 调整，`--upload-jobs 1` 用于串行排障；远端多余资产清理、同名资产删除/替换准备和最终校验必须保持顺序执行。
- `发布.py` 上传 Release 资产时必须登记活跃上传连接，Ctrl+C 时主动关闭连接；上传循环按 chunk 检查取消信号，重试等待使用可中断等待。
- `发布.py` 生成 `SHA256SUMS.txt` 时可以并行计算各资产摘要，但输出顺序和文件格式必须保持稳定。
- Windows portable 发布 zip 使用本地 manifest 记录目录文件名、大小和 mtime；manifest 命中时可复用已有 zip，manifest 文件不得作为 Release 资产上传，最终仍以发布资产一致性校验为准。
- `编译.py` 在 WSL Linux 且仓库位于 `/mnt/*` 时，默认把源码复制到 WSL 原生临时目录执行 Linux 构建，排除 `node_modules`、构建输出和发布临时目录，成功后把 installer 合并回 `app/build`，并把 portable、kernel、前端和 web clipper 产物回拷到当前仓库；需要复现旧流程时使用 `--no-wsl-native`。
- Electron 和 electron-builder 二进制下载镜像可由环境变量覆盖；脚本默认使用 `ELECTRON_MIRROR` 与 `ELECTRON_BUILDER_BINARIES_MIRROR` 的国内镜像兜底，降低 Linux 打包下载失败概率。
- Arch/WSL 等缺少 `libcrypt.so.1` 的 Linux 环境打包 `.deb` 时，`编译.py` 可临时解压 `libxcrypt-compat` 到 `.tmp/linux-fpm-compat` 并通过 `LD_LIBRARY_PATH` 供 electron-builder 内置 fpm 使用；不得要求用户手动污染系统环境。

## 笔记树加载稳定性

- `filesys.LoadTree` 可以复用原始 JSON 字节缓存，但每次调用必须重新解析并返回独立的 `*parse.Tree` 实例。
- 树缓存中的原始 JSON 字节按不可变数据处理，写入缓存和读取缓存时都必须复制切片，避免调用方共享可变底层数组。
- 禁止缓存并复用可变的 parsed tree 指针；调用方会在加载、渲染、索引和事务过程中修改 tree/root 字段，复用实例会造成跨笔记加载状态污染。
- `model.GetDoc` 等只读渲染路径必须使用 detached AST 副本承载高亮、虚拟引用、引用计数和临时 IAL 等展示态变更，禁止把源 tree 节点直接移动到渲染临时树。
- `WriteTree` 写入已有非空文档时禁止用空 AST 覆盖磁盘内容；如果内存 tree 为空但目标文件已存在且非空，必须失败关闭并保留原文件。
- `WriteTree` 落盘必须使用临时文件安全写入，不得先 truncate 原 `.sf` 文件再写入；写入失败时应尽量保留原笔记文件。
- 文档列表、索引扫描等读取路径不得因为 IAL 缺失或文件名异常自动移动/删除 `.sf` 文件；只能记录警告、跳过展示或交由显式修复流程处理。
- `/api/filetree/listDocTree` 只能在目标笔记本根目录内递归，入口路径必须通过 `ResolvePathUnder` 归一化；递归扫描只接受合法块 ID 目录和合法 `.sf` 文档文件。
- 文档列表读取 IAL 中的 `id` 必须校验，不合法时优先回退文件名 ID，避免坏 IAL 导致列表渲染 panic。
- 文档读取前必须等待事务队列完成，避免打开笔记时读取到未完成写入状态。
- 事务 large insert/delete 快路径必须把加载、插入、删除错误返回给 `performTx` 并触发回滚；非法块 ID 必须先失败关闭，禁止继续查询块树或吞掉错误后提交部分变更。
- 事务队列、单事务提交等待和 SQL 写队列等待必须有超时与诊断日志，禁止无界等待导致前端永久卡死。
- 导入 `.sf.zip` / `.zip` 时必须先校验 notebook ID，上传写入临时文件前必须限制文件大小，并在解压时限制文件数量、单文件大小、总解压大小、压缩比和路径穿越。
- `/api/file/putFile` 等普通文件上传不得整文件无界读入内存；必须限制上传大小、使用流式写入、关闭上传句柄，并通过临时文件安全写入保留原目标文件。
- 临时文件安全写入在 reader/copy/sync/chmod/rename 任一失败路径都必须释放文件句柄并清理临时文件，避免失败上传留下资源泄漏或污染目录。
- 普通资源上传必须限制单次文件数量、单文件大小和总大小；上传限制不依赖真实外部服务，PicGo 与本地上传入口共享同一文件头校验。
- HPath 计算暂不使用独立短期缓存，避免父文档重命名、移动、重建索引后路径显示陈旧。
- `model.NewLute()` 默认返回新实例；除非建立完整 reset/borrow/release 生命周期和测试，否则不得池化可变 Lute 对象。
- SQL 查询批量块 ID 时必须使用参数化占位符，禁止拼接块 ID 到 SQL 字符串。
- `SearchDocs` 文档搜索必须使用参数化 SQL；搜索关键词、name/alias/memo 条件和排除 ID 只能作为查询参数传入，禁止拼接到 SQL 字符串。
- 笔记本文件路径必须先归一化为仓库内相对路径，再通过 `ResolvePathUnder` 解析到笔记本根目录下；文件列表、移动、删除、创建目录等操作不得接受 `..`、绝对路径或卷标路径越界访问。
- Protyle 正文加载和 SourceFlow 内部粘贴必须以保留笔记 Block DOM 为优先：不得对完整笔记内容使用 `DOMPurify.sanitize` 的标签/属性空白名单配置，不得因安全过滤剥离业务标签、`data-*` 属性或块结构。
- SourceFlow 是本地笔记软件，笔记业务允许保存和渲染用户写入的完整 HTML/Block DOM；后续安全加固只能在不破坏笔记结构和既有内容语义的前提下局部处理。

## 文档树拖拽

- 文档树拖拽增强分两阶段推进：先增强移动可用性，再拆分排序交互。
- 阶段一不自动切换自定义排序；普通文档树拖拽只表达移动，必须在任意排序模式下可用。
- 阶段一移动落点包括目标文档、笔记本根节点、已展开目录空白区和子列表末尾；落点语义统一为“移动到该目录或文档下”，同父目录拖放视为无操作。
- 拖拽移动继续使用现有 `/api/filetree/moveDocs` 后端接口，并保留只读模式禁用、父文档禁止移动到自身子树、无效落点不提交等安全边界。
- 普通文档树拖拽不再调用 `/api/filetree/changeSort` 或 `/api/notebook/changeSortNotebook`；排序入口独立于拖拽移动。
- 文档自定义排序通过右键菜单“向上移 / 向下移”调整同级顺序，继续使用 `/api/filetree/changeSort` 提交。
- 块标拖拽转文档属于编辑器块转换路径，阶段一保持既有 `heading2Doc` / `li2Doc` 行为。

## 文档树外观

- 文档树外观增强不改变移动、排序或数据语义，只改善层级识别和拖拽反馈。
- 拖拽落点提示、当前路径/选中项/拖拽目标状态区分、可展开目标等待反馈默认启用。
- 文档树层级引导线作为外观配置提供，默认关闭。
- 文档树密度作为外观配置提供，取值为紧凑、默认、宽松；默认保持当前行距。
- 文档树字号作为外观配置提供，`0` 表示使用主题默认字号；用户可在设置页输入 `10-20px`，前端和后端都会做边界归一化。
- 文档树子文档数量作为外观配置提供，默认关闭；开启后仅在有子文档的条目右侧显示弱化数字，`0` 不显示。
- 文档树全部笔记总数作为外观配置提供，默认开启；顶部标题栏右侧以轻量胶囊显示已打开笔记本下的文档总数。
- 文档树空白区域右键复用顶部“更多”菜单，作为新建笔记、重建索引、排序和发布权限等全局文档树操作的低成本入口；该入口不改变文档行、笔记本根行和多选文档的既有右键菜单语义。
- 设置入口放在“设置 > 外观 > 文档树”，配置写入外观配置，不引入独立配置文件。
- 外观配置字段为 `appearance.fileTreeGuides`、`appearance.fileTreeDensity`、`appearance.fileTreeFontSize`、`appearance.fileTreeDocCount` 与 `appearance.fileTreeTotalCount`，后端对密度和字号做归一化。
- 文档树面板通过 `file-tree--guides`、`file-tree--density-*`、`file-tree--doc-count`、`file-tree--total-count`、`file-tree__item--current` 与 `--sf-file-tree-font-size` 等状态表达外观；拖拽落点提示通过 `data-drop-label` 和 `data-drag-expand` 表达。

## 编辑器结构提示

- 笔记编辑页结构提示只改善阅读与定位，不写入文档内容，不改变块数据、Markdown 导入导出或编辑事务语义。
- 标题层级通过标题文字左侧常驻 `H1` - `H6` 标识表达，覆盖编辑区内可见标题，避免只依赖字号判断标题层级。
- 当前稳定版本只保留配置字段 `editor.displayHeadingLevel`。
- `displayHeadingLevel` 默认开启，满足标题层级默认可见。
- 前端通过 Protyle WYSIWYG 容器类控制显示，样式使用伪元素渲染结构提示，不参与编辑内容保存。
- `displayBlockLineNumber` 与 `alwaysShowGutter` 已因稳定性问题移除，后续若恢复必须重新评估异常边界并补足回归测试。

## 易用性增强路线

- 本轮易用性增强分三阶段推进，所有阶段均不改变文档移动、排序、块数据或 Markdown 语义。
- 阶段一聚焦文档树导航：快速过滤、当前文档路径条、最近编辑入口、常用文档入口轻量版、文档树状态标识。
- 阶段二聚焦正文定位：正文内 Sticky 当前标题、正文与大纲双向高亮、标题折叠体验增强。
- 阶段三聚焦整理与引用：空文档/重名文档提示、块级定位链接复制增强；孤立文档暂不处理，避免误报和额外扫描成本。
- 文档树快速过滤作为文档树局部导航能力，不替代全局搜索；过滤结果显示匹配项和路径上下文。
- 文档树状态标识第一阶段仅使用已有低成本数据：书签、子文档、引用数；附件/任务状态需要可靠数据源时再扩展。
- 最近编辑入口优先复用已有 recent-doc 存储与 `/api/storage/getRecentDocs`，不新建独立历史数据结构。
- 常用文档入口第一阶段使用最近浏览记录作为轻量口径，不新增频次统计表。
- 最近编辑与常用文档快捷分组首次展示默认折叠；一旦本地存在 `file-tree-nav-collapsed` 用户状态，必须以用户状态为准。
- 正文定位增强不改变标题块数据和折叠事务语义；滚动时仅根据当前可见标题同步大纲焦点和正文视觉状态。
- Sticky 当前标题作为编辑器内容区内的只读浮层展示，不写入文档内容；标题折叠增强仅增加视觉提示，不改变 `fold`/`heading-fold` 数据。
- 空文档和重名文档提示只作为当前编辑器的被动整理提示，不自动改名、不自动移动、不创建清理任务；孤立文档仍不处理。
- 重名文档提示复用现有 `/api/filetree/searchDocs`，按当前文档标题做精确同名过滤；块级定位链接复用已有块引用文本、层级路径和 `sf://blocks/` 协议，不新增链接数据结构。
