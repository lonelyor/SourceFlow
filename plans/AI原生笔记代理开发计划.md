# AI 原生笔记代理开发计划

更新日期：2026-06-02

## 1. 定位

AI 是 SourceFlow 的独立原生笔记助手，不属于工作台，也不替代工作台。

AI 的长期目标是成为可控制整个软件的智能控制层：能读取、理解、组织、修改和执行笔记软件内的操作，但所有行为必须经过权限、安全、审阅和审计约束。

## 2. 产品能力目标

SourceFlow AI 要同时吸收三类成熟产品能力：

- Notion AI：工作区内 AI、内联写作、工作区搜索、计划审阅、创建和编辑页面/数据库。
- Tana AI：从任意笔记直接开启聊天，用 `@` 引用具体笔记或节点上下文，侧边栏保存会话和模型选择。
- NotebookLM：以用户选择的 sources 为中心，围绕指定资料回答、生成和显示来源。

SourceFlow 的实现口径：

- 独立 AI 侧边栏默认固定。
- 笔记、选区、文档树、文件夹、附件、搜索结果都能直接触发 AI。
- 输入框支持引用 `@当前笔记`、`@选区`、`@笔记`、`@文件夹`、`@附件`、`@搜索结果`、`@工作台视图`。
- AI 写入默认生成 patch/diff，用户接受后才正式写入。
- 多 provider/profile 保存，调用时可选择使用哪个 AI。

## 3. 底层架构

### 3.1 入口层

- 侧边栏 AI Dock。
- 编辑器选区菜单。
- 笔记标题菜单。
- 文档树右键菜单。
- 文件夹和附件上下文菜单。
- 搜索结果操作入口。

### 3.2 上下文层

- 所有引用统一建模为 source。
- source 类型包括 note、selection、block、folder、attachment、search-result、workbench-view。
- 文件夹和大量笔记引用先构建摘要包，不无界读取全文。
- AI 可以按权限请求继续读取 source 详情。
- 回答应尽量带来源引用，特别是跨笔记、文件夹和附件问答。

### 3.3 Profile 层

- 保存多个 AI 配置。
- 支持手动选择 profile。
- 支持默认 profile、写作 profile、长上下文 profile、本地隐私 profile。
- profile 只决定模型调用，不决定是否绕过安全。

### 3.4 权限层

三种权限模式：

- 默认权限：默认只读和生成建议；写入必须 patch 审阅。
- 自动审查：低风险写入可快速确认，中高风险自动升格人工确认。
- 完全访问权限：允许更主动的读写执行，但仍受硬护栏、黑白名单和审计约束。

三类能力：

- 可读：笔记、块、文件夹、附件、搜索、元数据、历史。
- 可写：创建、插入、替换、移动、重命名、标签、属性、删除单篇笔记。
- 可执行：索引、导入导出、批量任务、软件命令、工作台对象创建。

黑白名单：

- 支持按笔记本、文件夹、笔记、标签、附件类型和工具类型限制。
- 黑名单优先级高于白名单。
- 附件默认只读，写入/删除附件必须单独授权。

## 4. 安全内核

### 4.1 笔记层安全

- AI 不直接写文件系统。
- 所有写入走笔记原生 API、事务和 patch apply。
- 写入前校验目标存在、目标授权、before 内容一致、路径未越界。
- 删除块和替换块不得作用于根文档块。
- 外部 Markdown 写入必须重新生成块 ID。
- 写入结果必须审计，低风险操作支持回滚。

### 4.2 AI 层安全

AI 层安全负责判断模型意图、工具计划和绕过行为。

出现以下行为时必须暂停：

- 要求关闭或绕过安全检查。
- 要求静默执行或不要用户确认。
- 试图分批规避批量阈值。
- 用低风险工具组合达成高风险结果。
- 用移动、导入、同步、覆盖间接达成全量删除或全量替换。
- 直接调用底层文件 API。
- 使用“全部”“所有”“整个库”等模糊大范围目标但没有影响清单。

### 4.3 硬禁止

AI 永远不能执行：

- 删除整个工作空间。
- 删除整个笔记本。
- 清空所有笔记。
- 清空某个笔记本下全部笔记。
- 重置工作空间数据。
- 用导入、同步、覆盖、迁移等方式变相替换整个工作空间或笔记本。
- 将全量笔记批量替换为空。
- 将全部笔记移动到废纸篓后自动清空。

这类需求只能转成清理建议、风险报告或人工操作清单。

### 4.4 批量阈值

- 单次任务触达 `>= 10` 篇笔记的修改、删除、移动、重命名、属性批改，必须人工确认。
- 阈值按同一会话、同一 Agent 任务和同一用户目标累计计算。
- AI 不能拆成多次 9 篇规避确认。

## 5. 开发阶段

### 阶段 1：固定入口和可用对话

- AI 侧边栏默认固定。
- 空配置显示明确引导和 fake provider 本地体验入口。
- 多 profile 选择进入主对话。

### 阶段 2：上下文引用

- 实现 `@当前笔记`、`@选区`、`@笔记`、`@文件夹`。
- 文件夹引用生成摘要包和 source ID。
- 回答显示来源。

### 阶段 3：权限与黑白名单

- 实现默认权限、自动审查、完全访问权限。
- 实现可读、可写、可执行能力开关。
- 实现黑白名单。

### 阶段 4：安全内核

- 实现硬禁止规则。
- 实现 `>= 10` 篇批量确认阈值。
- 实现绕过护栏检测。
- 工具调用和 patch apply 前强制校验。

### 阶段 5：笔记操作闭环

- 文档树、标题菜单、选区、文件夹触发 AI。
- 写入型结果进入 patch 审阅。
- 接受后正式事务写入。
- 审计与低风险回滚。

### 阶段 6：附件和 sources 模式

- 附件作为 source 引用。
- 文本类附件可读内容，二进制先只读元数据。
- 支持勾选/排除 sources。
- 类 NotebookLM 的资料型问答和报告生成。

### 阶段 7：批量 Agent

- 批量任务逐项执行。
- 暂停、恢复、取消、失败重试。
- 每项输出 patch，逐项审阅。
- 大规模操作必须进入人工确认影响清单。

## 6. 验收标准

- AI 侧边栏默认可见。
- 可正常发起对话。
- 可引用笔记、选区、文件夹、附件。
- 多 profile 可选择。
- 三种权限模式可用。
- 黑白名单和读写执行权限生效。
- 删除工作空间、笔记本或全量笔记集合被硬拦截。
- 触达 `>= 10` 篇笔记的批量操作必须人工确认。
- 绕过护栏意图被识别并暂停。
- 写入默认 patch 审阅。
- 审计记录可查看，低风险写入可回滚。
