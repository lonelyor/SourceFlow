# 编辑器跨块复制粘贴安全强化设计

日期：2026-06-05

## 状态

- 本文为设计阶段文档，不改变现有代码行为。
- 该设计会改变复制/粘贴边界判定，属于高影响编辑器行为调整；代码落地前需要用户确认。
- 目标是先消除误伤其他块的风险，再逐步补齐更完整的跨块文本替换体验。

## 问题结论

用户反馈：在某个块中复制粘贴大段内容时，如果内容本身不换行，有概率复制到其他块；手动换行后粘贴则没有问题。

代码审计确认存在风险路径：

- 普通正文块通过 CSS 软换行显示长文本，`word-break: break-word` 与 `white-space: break-spaces` 只影响视觉排版，不形成真实块边界。
- 普通文本选择如果跨过多个块，当前复制链路仍可能把包含 `[data-node-id]` 的片段写入 SourceFlow 内部剪贴板 MIME。
- 粘贴时内部 MIME 会被当作 Block DOM 处理，可能从“我只想复制文本”变成“复制了块结构”。
- `insertHTML()` 在 inline 粘贴路径中直接执行 `range.deleteContents()`，但事务只记录起始块 old/new HTML；如果 range 实际跨块，可能先修改多个块 DOM，再只提交单块事务。

这类问题的核心不是 Markdown 解析，也不是后端数据层，而是前端编辑器 selection、剪贴板 MIME 和事务边界不一致。

## 设计目标

1. 单块文本操作只能修改单块。
2. 块级复制粘贴只能由明确块选择触发。
3. 普通文本选择即使跨块，也不能伪装成内部 Block DOM 粘贴。
4. 跨块选择不得使用单块 `update` 事务包装。
5. 任何无法证明安全的跨块粘贴必须失败关闭，不得先改 DOM 再补救。
6. 所有变更必须保持撤销/重做原子、可审计、可回滚。
7. 不通过自动插入换行、截断文本或改变正文 CSS 来规避问题，避免改变用户笔记内容语义。

## 非目标

- 不改变用户笔记中的真实换行、空格、Markdown 语义。
- 不改变显式块选择、块菜单复制、块拖拽和块移动语义。
- 不重写整个 Protyle 粘贴系统。
- 不引入新的配置项让用户承担安全边界选择。

## 人类直觉语义

### 复制

- 光标在块内且没有选区：复制当前块，沿用现有块复制语义。
- 显式块选择：复制块，写入 SourceFlow 内部 Block DOM MIME。
- 单块文本选区：复制文本和安全的行内格式；如果片段不包含 `[data-node-id]`，可以写入行内 SourceFlow MIME。
- 跨块文本选区：复制用户选中的文本内容和标准 HTML 展示片段，但不写入 SourceFlow 内部 Block DOM MIME。
- 表格/数据库视图专用选择：继续走现有表格/AV 专用路径。

### 粘贴

- 光标处粘贴普通文本：插入到当前块或按 Markdown 自然解析。
- 单块文本选区上粘贴：只替换当前块内选区。
- 显式块选择上粘贴块：按块级替换/插入语义处理。
- 普通跨块文本选区上粘贴：第一阶段失败关闭并提示，后续只有在实现多块事务后才允许直接替换。
- 内部 Block DOM 粘贴：只接受来自显式块选择或可信块复制的内部 MIME。

## 核心不变量

### Selection Scope

新增统一选择范围判定模块，建议路径：

- `app/src/protyle/util/selectionScope.ts`

核心类型：

```ts
type TSelectionScopeKind =
    | "collapsed"
    | "single-block-text"
    | "multi-block-text"
    | "explicit-block"
    | "table"
    | "attribute-view"
    | "code"
    | "unsupported";
```

核心 API：

```ts
interface ISelectionScope {
    kind: TSelectionScopeKind;
    startBlock?: HTMLElement;
    endBlock?: HTMLElement;
    blockIds: string[];
    crossesBlock: boolean;
    containsBlockDOM: boolean;
    isExplicitBlockSelection: boolean;
}

resolveSelectionScope(range: Range, wysiwygElement: HTMLElement): ISelectionScope
assertInlineRangeWithinSingleBlock(scope: ISelectionScope): boolean
canWriteInternalSourceFlowClipboard(scope: ISelectionScope, fragment: DocumentFragment): boolean
```

判定规则：

- `collapsed`：无选中文本，且 range 在编辑器内。
- `single-block-text`：start/end 都落在同一个 `[data-node-id]` 内，且不是显式块选择。
- `multi-block-text`：start/end 落在不同 `[data-node-id]` 内，且不是显式块选择。
- `explicit-block`：存在 `.protyle-wysiwyg--select` 或明确块菜单/块选择来源。
- `table` / `attribute-view`：保持专用选择路径优先级。
- `unsupported`：无法确认边界时失败关闭。

## 复制强化

修改位置：

- `app/src/protyle/wysiwyg/commonEvents/copy.ts`

设计：

1. 复制入口先调用 `resolveSelectionScope()`。
2. 只有以下场景允许写入 `Constants.SOURCEFLOW_HTML_CLIPBOARD_MIME`：
   - `explicit-block`
   - 当前已有块菜单或 gutter 块复制路径
   - `single-block-text` 且复制片段不包含任何 `[data-node-id]`，只包含行内 span、link、ref、mark、emoji 等安全行内节点
3. `multi-block-text` 不写内部 MIME，只写：
   - `text/plain`：按选区顺序输出文本，块边界归一化为单个换行
   - `text/html`：标准 HTML 展示片段，移除 `data-node-id`、`updated`、`contenteditable`、`spellcheck` 等块运行时属性
4. 如果 range.cloneContents() 中出现 `[data-node-id]`，但 scope 不是 `explicit-block`，必须降级为普通文本/标准 HTML。

这样用户从一个长段里拖选文本时，即使浏览器 range 包含了相邻块结构，也不会在粘贴时被当作块复制。

## 粘贴强化

修改位置：

- `app/src/protyle/util/paste.ts`
- `app/src/protyle/util/insertHTML.ts`

设计：

1. `paste()` 读取内部 MIME 后先校验来源和目标 scope。
2. 如果剪贴板含 SourceFlow 内部 MIME，但目标是普通 inline 文本替换，必须确认 MIME 不包含块节点；否则按块级粘贴处理。
3. `insertHTML()` 在任何 `range.deleteContents()` 前必须做 scope 守卫：
   - inline 路径只允许 `collapsed` 或 `single-block-text`
   - `multi-block-text` 直接返回失败，不执行 DOM 删除
   - `explicit-block` 走块级事务路径，不走单块 update
4. 所有失败关闭都必须在 DOM 修改前发生，并给出简短提示：
   - “当前选择跨越多个块。为避免误改其他块，请使用块选择复制/粘贴，或只选择单个块内文本。”
5. 后续实现多块文本替换时，必须新增独立事务构造器，不能复用单块 `insertHTML()` 的直接 DOM 删除路径。

## 多块文本替换后续方案

第一阶段不直接支持普通跨块文本选区粘贴替换，优先保证不会误伤。

后续如果要完整支持，需要新增专用事务：

- 对 startBlock、endBlock 和中间块分别生成 oldHTML 快照。
- 先在 detached DOM 中模拟替换，生成每个受影响块的 newHTML。
- 事务必须包含所有受影响块的 `update/delete/insert` 操作。
- 任一块无法解析、无法定位或包含不支持结构时，整体失败关闭。
- 不允许直接对真实 DOM 执行 `range.deleteContents()` 后再推导事务。

## 用户提示策略

提示只在真实阻断时出现，不增加常规复制粘贴噪音。

推荐文案：

- 中文：`当前选择跨越多个块。为避免误改其他块，请使用块选择复制/粘贴，或只选择单个块内文本。`
- 英文：`The current selection spans multiple blocks. To avoid editing other blocks, use block selection or select text within a single block.`

不弹确认框，因为确认框会让用户在不理解风险时继续执行；此类问题应失败关闭。

## 分阶段落地

### 阶段 1：防误伤安全闸

- 新增 selection scope helper。
- 复制时限制内部 MIME 写入条件。
- 粘贴时禁止普通跨块文本选区进入单块 inline 删除路径。
- 补静态/DOM 回归测试。

阶段 1 会带来一个行为变化：普通跨块文本选区上直接粘贴会被阻断并提示。该变化是有意的安全收紧，避免误删或误改其他块。

### 阶段 2：完整多块文本替换

- 新增 detached DOM 多块替换事务构造器。
- 支持普通跨块文本选区被粘贴内容替换。
- 所有受影响块必须纳入同一个事务。
- 保留阶段 1 的失败关闭兜底。

阶段 2 复杂度更高，建议在阶段 1 稳定后独立推进。

## 设计评审

结论：设计通过，可以作为后续实现依据。

关键理由：

- 不改变笔记正文语义，不靠自动换行规避问题。
- 将文本选择和块选择严格分离，符合块编辑器用户直觉。
- 第一阶段以失败关闭换取数据安全，避免高影响编辑器路径继续隐式跨块写入。
- 后续多块替换有明确事务模型，不复用当前单块 `range.deleteContents()` 路径。
