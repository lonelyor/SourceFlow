# SourceFlow 测试与稳定性门禁

本文档定义当前稳定阶段必须覆盖的自动化/半自动化测试范围。新功能开发不得绕过这些门禁。

## 必跑命令

```bash
python 编译.py --stability-gate-only
```

门禁包含：

- 脚本语法检查：`编译.py`、`发布.py`、`插件商城.py`、`诊断包.py`。
- SourceFlow 架构审计：禁止重新引入旧品牌/旧架构命名作为新真相源。
- Kernel 回归测试：`go test -vet=off ./...`。
- 插件隔离冒烟：manifest、权限声明、包完整性、商城提交哈希。
- 前端类型检查：`pnpm --dir app run typecheck`。

## 安装包/便携包主流程 E2E

`编译.py` 在验证 Windows 安装包与便携包时会启动真实内核，使用临时工作区执行：

- 创建笔记本。
- 创建 Markdown 笔记。
- 编辑笔记内容。
- 上传附件并验证笔记引用。
- 搜索唯一标记。
- 导出 Markdown 内容并校验正文。
- 从本地 Markdown 文件导入笔记。
- 初始化仓库密钥并创建历史快照。
- 配置本地同步源、执行同步上传、读取同步诊断。
- 加载插件列表，确认插件系统不影响主流程。
- 强杀内核模拟异常退出，再用同一临时工作区重启。
- 重启后再次搜索创建/导入的笔记标记，确认数据没有丢失。

临时工作区和同步目录测试结束后自动删除。

`发布.py` 默认不重复编译或重复跑本地 E2E；它只消费已经测试过的构建产物并执行发布操作。需要在发布阶段额外做本地包冒烟时，显式传入 `--validate`。

## AI 助手专项冒烟

AI 助手 Dock 相关变更还应单独运行：

```bash
pnpm --dir app run test:ai-dock-runtime
```

该脚本覆盖助手 Dock 的工具开关、模型切换和设置入口行为。

## 数据安全与可用性覆盖

当前自动覆盖：

- 异常退出：E2E 中强杀内核后重启验证主笔记数据仍可检索。
- 同步中断基础面：本地同步源配置、上传、诊断读取进入安装包/便携包验证。
- 插件崩溃隔离基础面：插件权限、包结构、运行时加载进入门禁。
- AI 助手隔离基础面：助手 Dock 运行时、工具开关和模型切换进入前端冒烟；AI 或工具调用失败时不得影响主笔记编辑、搜索和同步。
- 数据库可重建基础面：Kernel 回归测试覆盖工作区配置归一化、同步本地路径、插件安装等关键路径。

仍需半自动/人工覆盖：

- 真实断电场景。
- 人为破坏 SQLite 数据库后的恢复体验。
- 多设备同时编辑造成的真实冲突恢复。
- 操作系统级崩溃 dump 与诊断包分析链路。

这些项目不能伪造为自动通过，发布前必须在发布清单中记录测试结果。

## 唯一真相源与归一化

- 工作区配置唯一真相源为对象格式：`{"workspace": "...", "workspaces": [...]}`。
- 旧数组格式只作为迁移输入，写回时必须归一化为对象格式。
- 新功能不得再把思源旧结构作为 SourceFlow 的运行时真相源。
- 需要兼容旧数据时，只允许在边界层迁移，内部状态必须归一化。

## 发布阻断规则

以下任一失败即不得发布：

- `go test` 失败。
- 前端 typecheck 失败。
- 插件隔离冒烟失败。
- 安装包或便携包缺少关键文件。
- 安装包或便携包内核无法启动。
- 主笔记流程 E2E 或异常退出重启验证失败。
- 发布资产版本号与当前版本不一致。
