# SourceFlow 产品级质量清单

本文档只关注软件稳定性、兼容性、可用性和数据安全。

## 质量目标

- 主笔记流程稳定：创建、编辑、附件、搜索、导入导出、历史、同步、冲突恢复不能被附加功能破坏。
- 数据安全优先：异常退出、同步中断、插件异常、配置迁移都不能导致笔记数据丢失。
- 安装包和便携包同等重要：二者都必须能启动、写入工作区、重启后保留数据。
- 插件可熔断：插件失败只影响插件自身，不影响记笔记、搜索和同步。
- AI 助手可熔断：AI 对话、图片输入、工具调用或模型配置失败，只影响助手流程，不影响记笔记、搜索和同步。
- 跨平台兼容：Windows、macOS、Linux 的构建脚本、路径处理、依赖检测和产物校验应保持一致。

## 门禁要求

每次发布前至少运行：

```bash
python 编译.py --stability-gate-only
```

生成安装包或便携包时，`编译.py` 还必须执行真实内核 E2E：

- 创建笔记本和笔记。
- 编辑笔记。
- 上传附件。
- 搜索唯一标记。
- 导入 Markdown。
- 导出 Markdown。
- 创建历史快照。
- 执行本地同步并读取同步诊断。
- 加载插件列表。
- 强杀内核并重启同一工作区验证数据仍可检索。

## 兼容性要求

- 工作区配置唯一真相源为 `{workspace, workspaces}` 对象格式。
- 旧数组格式只作为迁移输入，写回必须归一化。
- 新架构只保留 SourceFlow 自身语义，不再把思源旧结构作为运行时真相源。
- 路径处理必须覆盖 Windows、macOS、Linux，避免硬编码分隔符。
- macOS M 系列、Windows x64、Linux x64/arm64 的构建入口必须由 `编译.py` 统一调度。

## 可用性要求

- 编译失败必须给出明确原因。
- 发布脚本只消费已有产物，不触发编译或本地 E2E；必须阻止旧版本产物混入。
- 诊断包必须能本地生成，便于定位崩溃、配置和工作区状态。
- 插件权限必须在安装/启用前可见。
- AI 工具调用权限、读写范围和审计记录必须在助手界面中可见。
- 附加功能失败时，主笔记流程必须继续可用。

## 工程边界

- 只记录能通过本仓库脚本、测试、文档和本地诊断落实的事项。
- 外部运营事项不进入构建或发布门禁。
- 无法自动验证的真实设备、真实断电、多设备冲突场景，必须在人工测试记录中明确标注。
