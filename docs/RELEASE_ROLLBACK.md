# SourceFlow 发布与回滚策略

## 发布前

必须完成：

```bash
python 编译.py --stability-gate-only
```

构建发布资产时，安装包和便携包同等重要，必须由 `编译.py` 同时验证：

- 包内关键文件完整。
- 内核可启动。
- 主笔记流程 E2E 通过。
- 异常退出后同一工作区可恢复。
- 资产版本号等于当前版本。
- SHA256SUMS 已生成。

发布阶段只消费已经编译和本地测试过的产物，执行导出公开仓库、整理发布资产、生成 SHA256、推送 tag 和上传 GitHub Release；不重复编译。

## 暂停发布条件

出现以下任一情况，暂停发布：

- 主流程 E2E 失败。
- 安装包或便携包无法启动。
- 工作区配置无法读取或无法归一化。
- 笔记创建、编辑、搜索、导入导出任一主流程失败。
- 同步导致数据丢失或无法恢复。
- 插件加载影响主笔记流程。
- 发现密钥、token、私钥进入发布资产。

## 回滚流程

1. 停止上传新资产，暂停当前 Release 的推广入口。
2. 在 Release 说明顶部添加醒目说明：受影响版本、问题摘要、建议动作。
3. 恢复上一个稳定版本的下载入口。
4. 保留问题版本资产用于排查，但标记为不推荐下载。
5. 打开 `type/regression` 或 `type/data-safety` issue，附诊断包和复现步骤。
6. 修复后仍使用当前稳定版本号策略；只在完成版本号、changelog、编译产物和发布资产一致性校验后切换到下一个补丁版本。

## 用户侧建议

涉及数据安全时，回滚说明必须提醒用户：

- 回滚前先备份工作区。
- 不要删除 `data/`、`conf/`、`repo/`。
- 如果使用同步，先查看同步诊断，必要时暂停同步。
