# SourceFlow v0.1.9

## Highlights

- Mermaid diagrams now follow the app theme: rendered blocks re-render on light/dark switch (including background tabs), use the app font stack, and get a card background in light mode.
- Mermaid blocks are more resilient: render failures can be retried via a refresh icon, errors render as multi-line text, and double-clicking a diagram opens the zoom/rotate/flip lightbox.
- Fixes the dynamic context budget for CJK notes: the frontend now estimates tokens the same CJK-aware way as the backend, so Chinese notes no longer consume 4x the real budget and blow small model windows.
- Resolves real context windows for Ollama models instead of falling back to defaults.
- Fixes a startup crash in source builds ("Cannot access 'X' before initialization") caused by an import cycle around the base plugin API.

## Editor

- Mermaid blocks re-render when the light/dark theme switches, including blocks in background tabs via an IntersectionObserver fallback.
- Mermaid is initialized once per theme instead of on every render, and follows the app font stack (`--b3-font-family`) instead of a hardcoded sans-serif.
- Light mode renders mermaid with a card background and rounded corners; dark mode stays transparent where mermaid draws light text.
- Render failures are recoverable: the retry state is kept clean for a re-render, mermaid's error element is null-checked, and errors display as multi-line text.
- Adds a refresh icon on mermaid blocks (same interaction as echarts).
- Double-clicking a mermaid diagram opens the viewerjs lightbox with zoom / rotate / flip, matching the existing image preview UX.

## AI Assistant

- The frontend note-context allowance is now CJK-aware (1 CJK rune ≈ 1 token), matching the backend estimator. Previously a flat x4 token-to-rune conversion gave Chinese notes 4x the real budget, overflowing small context windows and clamping the history budget to 0.
- Ollama models resolve their real context window from the provider API instead of using fallback defaults.

## Plugin System & Stability

- The base plugin API is built lazily at plugin-load time instead of eagerly at module init, fixing a TDZ crash ("Cannot access 'X' before initialization") that broke every source build at startup via the tabUtil → layout/util → plugin/loader import cycle.

## Validation

- Regenerated installer and portable packages matching `0.1.9` before release; no older version artifacts are reused.
- Passed Go kernel target tests, frontend TypeScript checks, product readiness / lint-budget gates.
