# SourceFlow v0.1.1

## Highlights

- Added and published the standalone plugin bazaar: `https://github.com/lonelyor/SourceFlow-plugins`.
- Added the `Paper Polish` plugin for focused reading and writing polish.
- The plugin bazaar is served through a static CDN with GitHub Pages retained as a fallback, and can provide plugin lists, package assets, and README content to SourceFlow.
- `编译.py` is now the self-contained build entrypoint for environment checks, dependency setup, frontend build, Go kernel build, installer packaging, and portable packaging.
- `发布.py` is now the self-contained release entrypoint for build orchestration, quality gates, asset staging, release notes, GitHub Release publishing, and checksum generation.

## Plugins And Bazaar

- The built-in plugin source points to `https://cdn.jsdelivr.net/gh/lonelyor/SourceFlow-plugins@main/version.json`.
- Bazaar loading now retries built-in mirrors so a single unreachable static source does not leave the plugin list empty.
- Bazaar source settings support manual version, stage, package, stat, and README CDN URLs.
- Plugin installation shows source, version, declared permissions, and `SHA-256` integrity summary before install.
- Installed plugins stay disabled until the user explicitly enables them.
- Permission changes require confirmation again, keeping optional plugin features isolated from core note workflows.

## Current Plugin

- `sourceflow-paper-polish`: a lightweight note polish plugin.
- Provides a top bar toggle, status bar state, default enablement, compact density, and soft contrast settings.
- Does not request network, workspace write, or host control permissions.
- Its README now includes a bazaar source setup guide for users who need manual configuration.

## Build And Release

- Windows, macOS, and Linux builds are unified under `编译.py`.
- Same-OS platform and architecture targeting is supported, including macOS arm64 and Windows x64.
- Missing Node.js, pnpm, Go, and platform toolchains are detected and installed when supported.
- Portable packaging no longer depends on an external `scripts/portable-build.js`.
- Publishing is unified under `发布.py`, targeting `lonelyor/SourceFlow` by default.
- Release notes, `SHA256SUMS.txt`, and GitHub Release assets are generated by the release script.
- The browser extension keeps an independent version and is not bumped just because the app version changes.

## Stability Fixes

- Fixed kernel startup after switching workspaces when Electron writes object-form `workspace.json`.
- `workspace.json` now treats object format `{workspace, workspaces}` as the SourceFlow single source of truth; legacy arrays are only migration input and are normalized on write.
- Added workspace configuration regression tests for reading Electron object format, writing object format, and selecting the current workspace at startup.
- Added a unified stability gate through `npm run test:stability`, covering script syntax, SourceFlow architecture audit, full Go regression tests, plugin isolation smoke tests, and frontend typecheck.
- `编译.py` now runs the stability gate before building; failing tests stop installer and portable package generation.
- `编译.py` validates installer and portable outputs after building: portable packages are checked and boot the kernel, while Windows installers are extracted without side effects, checked, and boot the extracted kernel.
- `发布.py` now runs the same stability gate by default so local verification and release validation stay aligned.
- `发布.py` validates both installer and portable packages before release; either package failing validation blocks publishing.
- Installer and portable validation now run the main note workflow E2E: note creation, editing, attachment upload, search, import, export, repository snapshot, local sync diagnostics, and plugin loading.
- Package validation force-kills the kernel to simulate an abnormal exit, then restarts the same temporary workspace and searches for the created notes again.
- Added product-quality documentation for testing gates, operations diagnostics, release rollback, plugin permissions, and the product quality checklist.
- Added `诊断包.py` for local redacted diagnostics packages. It does not include note bodies, upload to the network, or collect release secrets by default.
- Release asset staging now only accepts installer and portable artifacts for the current app version, preventing stale builds from entering a Release.
- Plugin Bazaar publishing avoids needless timestamp and Bazaar hash churn when re-publishing an unchanged plugin.

## Manual Test Focus

- Install from the installer, start the app, create and edit notes, restart, and verify persistence.
- Extract and start the portable package, then verify kernel startup and data directory writes.
- Open Bazaar, trust the source, switch to the Plugins tab, and verify `Paper Polish` appears.
- Install and enable `Paper Polish`, then verify the top bar entry, status bar, settings, and toggle behavior.
- Disable the plugin and confirm note editing, saving, and sync remain unaffected.
- Switch workspace and restart the app; `cannot unmarshal object into Go value of type []string` should not appear.

## Integrity

- Release assets include `SHA256SUMS.txt` for download verification.
- Plugin packages record `archiveSHA256`, shown as an integrity summary before installation.
- Browser extension assets use the extension manifest version, for example `sourceflow-page-saver-0.1.0.zip`.
