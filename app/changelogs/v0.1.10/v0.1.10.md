# SourceFlow v0.1.10

## Highlights

- Fixes the frequent "kernel crash while editing, then prompted to rebuild the index" loop. The root cause: any single transient filesystem error (backup/sync software briefly locking a file, iCloud interference, a permission hiccup) during the write burst that follows every block edit would kill the kernel via exit code 26, leaving the index flagged incomplete and triggering the rebuild-index prompt on next boot.
- `conf.json` writes (which happen on every block edit) now retry with backoff and show an error toast instead of terminating the kernel.
- Atomic file writes retry `rename` on permission errors (`os.ErrPermission`, "permission denied") in addition to Windows share violations.
- The 10-minute filesystem consistency check only escalates to a fatal exit after 3 consecutive failed checks, tolerating one-off interference; a failed rename inside the check now propagates instead of being silently ignored.
- All `filelock` permission/share-violation fatal exits are downgraded to normal error returns so callers handle locked files gracefully.
- Task handlers (including the index flush) run with panic recovery inside their goroutine, so an indexing panic can no longer take down the whole kernel.

## Verification

- End-to-end: with a read-only conf directory, inserting code blocks now logs retry warnings and the kernel keeps serving API requests; the previous build exited with code 26 in the same scenario.
- Go kernel target tests, frontend TypeScript checks, product readiness / lint-budget gates all pass.

## Data Safety

- The workspace-on-cloud-drive guard is preserved: the filesystem check still exits after repeated consecutive failures, keeping the protection against sync-client corruption.
